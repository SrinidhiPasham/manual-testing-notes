# Software Testing - Complete Questions & Answers

## 1. What is Software Testing? Why it is important?

**Answer:**  
Software Testing is the process of evaluating a software application to detect defects and ensure it meets requirements. Software testing is important because it ensures software quality, prevents defects early, enhances security and performance, and improves user experience.

---

## 2. What is Quality Assurance?

**Answer:**  
Quality Assurance is a process of making sure the software is developed correctly and preventing defects by following good processes throughout development.

---

## 3. What is Quality Control?

**Answer:**  
Quality Control is the process of checking actual software to identify defects and ensure it meets the required quality standards.

---

## 4. What is the difference between QA and QC?

**Answer:**  
QA is focused on preventing defects by improving the process, whereas QC is focused on finding defects in the actual product.

---

## 5. What is Verification?

**Answer:**  
Verification is verifying software documentation that is being produced, such as Software Requirement Specifications, design documents, and user stories. It is known as Static Testing.

---

## 6. What is Validation?

**Answer:**  
Validation is when we launch the application and verify that the functionalities being built are actually in line with the requirements. It is known as Dynamic Testing.

---

## 7. What is SDLC?

**Answer:**  
SDLC stands for Software Development Life Cycle. It is a structured process followed to develop and maintain software.

The main phases are:

**Requirement Analysis → Design → Development → Testing → Deployment → Maintenance**

---

## 8. What is STLC?

**Answer:**  
STLC stands for Software Testing Life Cycle. It defines the activities performed during the testing process.

- **Requirement Analysis:** Testers analyze what features need testing.
- **Test Planning:** A strategy is created and it is decided what needs to be tested and by whom.
- **Test Case Development:** Testers write detailed test cases.
- **Environment Setup:** Setting up the testing environment.
- **Test Execution:** Running test cases, reporting bugs, and verifying fixes.
- **Test Closure:** Documenting everything for closure.

---

## 9. What is the difference between SDLC and STLC?

**Answer:**  
SDLC covers the complete software development lifecycle, whereas STLC specifically focuses on activities related to software testing.

---

## 10. What is the role of QA in SDLC?

**Answer:**  
QA plays an important role throughout SDLC. QA reviews requirements, identifies risks, prepares test cases, executes tests, reports and validates defects, performs regression testing, and supports release activities to ensure the software meets the required quality.

---

## 11. What are the levels of testing?

**Answer:**  
There are 4 main levels of testing:

1. Unit Testing – Tests individual components.
2. Integration Testing – Tests interaction between components.
3. System Testing – Tests the complete application.
4. Acceptance Testing – Verifies whether the system meets business and user requirements.

---

## 12. What are the different types of software testing?

**Answer:**  
Software Testing can be broadly categorized into **Functional Testing** and **Non-Functional Testing**.

**Functional Testing** verifies whether the application works according to the specified requirements.

Examples include:

- Functional Testing
- Smoke Testing
- Sanity Testing
- Regression Testing
- UAT

**Non-Functional Testing** verifies how well the application performs.

Examples include:

- Performance Testing
- Security Testing
- Usability Testing
- Accessibility Testing
- Compatibility Testing

---

## 13. What is Manual Testing?

**Answer:**  
Manual Testing is the process in which test cases are executed manually by a tester without using automation tools.

---

## 14. What is Automation Testing?

**Answer:**  
Performing testing with the help of tools and scripts is called Automation Testing.

---

## 15. What is Black Box Testing?

**Answer:**  
Black Box Testing is about testing what the software does. The tester focuses on testing the functionality of the software without knowledge of its internal code.

---

## 16. What is White Box Testing?

**Answer:**  
White Box Testing is about testing how the software works internally. The tester has knowledge of the internal code, logic, and structure.

---

## 17. What is Grey Box Testing?

**Answer:**  
Grey Box Testing is a testing technique where the tester has partial knowledge of the application's internal structure or implementation. It combines the approach of Black Box and White Box Testing.

---

## 18. What is Static Testing?

**Answer:**  
Static Testing is a type of testing performed without executing the software. It involves reviewing software documentation such as Software Requirement Specifications, design documents, and user stories.

---

## 19. What is Dynamic Testing?

**Answer:**  
Dynamic Testing is a type of testing where we execute the application and verify whether its functionality works as expected according to the requirements.

---

## 20. What is Functional Testing?

**Answer:**  
Functional Testing is a type of Black Box Testing that verifies whether the system behaves as expected according to the requirements.

---

## 21. What is Non-Functional Testing?

**Answer:**  
Non-Functional Testing checks qualities such as performance, security, usability, accessibility, and compatibility.

---

## 22. What is Positive Testing?

**Answer:**  
Positive Testing means testing the application with valid inputs to verify that it works as expected.

Example: For a login page, I enter a valid username and password and verify that I can log in successfully.

---

## 23. What is Negative Testing?

**Answer:**  
Negative Testing means testing the application with invalid or unexpected inputs to verify that it handles them correctly.

Example: For a login page, I enter an incorrect password and verify that the application displays an appropriate error message.

---

## 24. What is End-to-End Testing?

**Answer:**  
End-to-End Testing verifies the complete business flow of an application from start to finish to ensure that all components and integrations work together correctly.

---

## 25. What is Integration Testing?

**Answer:**  
Integration Testing is testing two or more modules or components together to verify that they communicate and work correctly with each other.

---

## 26. What is System Testing?

**Answer:**  
System Testing tests the entire system as a whole to verify its overall behavior and interaction between different components.

---

## 27. What is UAT?

**Answer:**  
UAT stands for User Acceptance Testing. It is the final testing phase where end users verify whether the software meets business requirements before release.

---

## 28. What is Exploratory Testing?

**Answer:**  
Exploratory Testing is a type of software testing where testers actively explore the application to find defects without predefined test cases.

We use it:

- When fast feedback is needed.
- When the application is complex.
- During early stages of testing.
- When dealing with tight deadlines.

---

## 29. What is Ad-hoc Testing?

**Answer:**  
Ad-hoc Testing is an informal type of testing performed without predefined test cases. The tester uses their knowledge and experience to identify defects.

---

## 30. What is Risk-Based Testing?

**Answer:**  
Risk-Based Testing prioritizes test cases based on risk factors, such as the likelihood of defects and their impact on the business.

---

## 31. What is Test Coverage?

**Answer:**  
Test Coverage is a measure of how much of the application or requirements are covered by testing.

---

## 32. What is a Test Plan?

**Answer:**  
A Test Plan is a document outlining the overall testing approach, objectives, scope, resources, and schedule.

---

## 33. What are Entry Criteria?

**Answer:**  
Entry Criteria are the conditions that must be met before testing can start.

---

## 34. What are Exit Criteria?

**Answer:**  
Exit Criteria are the conditions that must be met before testing can be completed or stopped.

---

## 35. What is a Test Environment?

**Answer:**  
A Test Environment is the setup required to test an application, including hardware, software, database, network, tools, and test data.

---

## 36. What is Test Data?

**Answer:**  
Test Data is the data used to execute test cases and verify whether the application behaves as expected.

---

## 37. What is a Defect?

**Answer:**  
A Defect is a flaw in the software that causes the actual result to differ from the expected result.

---

## 38. What is an Error?

**Answer:**  
An Error is a human mistake made during software development activities such as requirements, design, coding, or configuration.

---

## 39. What is a Failure?

**Answer:**  
A Failure occurs when the software executes and produces an incorrect or unexpected result.

---

## 40. When should testing start?

**Answer:**  
Testing should start as early as possible in the SDLC, ideally from the requirement phase. Early testing helps identify defects and requirement issues before they become expensive to fix.

---

## 41. What is Shift-Left Testing?

**Answer:**  
Shift-Left Testing means moving testing activities earlier in the SDLC so that defects and risks can be identified and fixed early.

---

## 42. What is a Test Scenario?

**Answer:**  
A Test Scenario is a high-level condition or functionality that needs to be tested. It describes what we need to test.

---

## 43. What is a Test Case?

**Answer:**  
A Test Case is a set of steps, test data, preconditions, and expected results used to verify a specific functionality. It describes how we test it.

---

## 44. What are the components of a Test Case?

**Answer:**  
A Test Case typically contains:

- Test Case ID
- Test Case Title
- Preconditions
- Test Data
- Test Steps
- Expected Result
- Actual Result
- Execution Status
- Comments or Test Evidence

---

## 45. What is a Test Suite?

**Answer:**  
A Test Suite is a collection of related test cases grouped together for execution.

---

## 46. What is a Test Script?

**Answer:**  
A Test Script is a sequence of instructions or steps used to execute a test. It can be written for manual execution or automation.

---

## 47. What is a Requirement Traceability Matrix?

**Answer:**  
A Requirement Traceability Matrix maps requirements with test cases. It helps verify that all functionality is covered according to customer requirements.

---

## 48. What is Test Execution?

**Answer:**  
Test Execution is the process of running test cases, comparing actual results with expected results, and recording the test status.

---

## 49. What are the possible Test Case statuses?

**Answer:**  
The common Test Case statuses are:

- Pass
- Fail
- Blocked
- Not Run
- Not Applicable

---

## 50. What is a Test Condition?

**Answer:**  
A Test Condition is a specific requirement, functionality, rule, or behavior that needs to be verified through testing.

---

## 51. What is a Test Objective?

**Answer:**  
A Test Objective defines what we want to achieve or verify through testing.

---

## 52. What is a Test Strategy?

**Answer:**  
A Test Strategy is a high-level document that defines the testing approach, scope, and tools.

---

# Defect Management

## 53. What is Defect Life Cycle?

**Answer:**  
Defect Life Cycle is the sequence of stages a defect goes through from the time it is identified until it is closed.

The common stages are:

**New → Assigned → Open/In Progress → Fixed → Retest → Verified → Closed**

The exact Defect Life Cycle may vary depending on the project or organization.

---

## 54. What is Severity?

**Answer:**  
Severity indicates how seriously a defect impacts the application's functionality.

---

## 55. What is Priority?

**Answer:**  
Priority indicates how urgently a defect needs to be fixed based on business impact and project requirements.

---

## 56. What is a Critical Defect?

**Answer:**  
A Critical Defect is a defect that has a very high impact on the application, such as application failure, data loss, security issues, or failure of a critical business function.

---

## 57. What is a Blocker Defect?

**Answer:**  
A Blocker Defect is a defect that prevents testing from continuing or blocks critical functionality.

---

## 58. What is a Defect Report?

**Answer:**  
A Defect Report is a record created by a tester to document an issue, including its steps, expected result, actual result, severity, and priority.

---

## 59. What should a good defect report contain?

**Answer:**  
It should contain:

- Clear Title
- Description
- Steps to Reproduce
- Expected Result
- Actual Result
- Severity
- Priority
- Environment
- Evidence

---

## 60. What is Retesting?

**Answer:**  
Retesting is performed to verify that a specific bug fix works as expected.

---

## 61. What is Regression Testing?

**Answer:**  
Regression Testing is done to make sure that new code changes have not impacted existing functionality.

---

## 62. What is Defect Leakage?

**Answer:**  
Defect Leakage occurs when a defect is missed during testing and is found in a later environment or production.

---

## 63. What is Defect Rejection?

**Answer:**  
Defect Rejection occurs when a reported issue is determined not to be a valid defect.

---

## 64. What is a Duplicate Defect?

**Answer:**  
A Duplicate Defect is an issue that has already been reported in another defect record.

---

## 65. What is a Deferred Defect?

**Answer:**  
A Deferred Defect is a valid defect whose fix is postponed to a future release.

---

# Test Case Design Techniques

## 74. What is Boundary Value Analysis?

**Answer:**  
Boundary Value Analysis is a Black Box Testing technique that focuses on testing the boundaries of input values, as errors are often found at the boundaries.

Example: If an input field accepts values from 1 to 100:

- Valid: 1 and 100
- Invalid: 0 and 101

---

## 75. What is Equivalence Partitioning?

**Answer:**  
Equivalence Partitioning is a Black Box Testing technique that divides input data into groups that are expected to behave in the same way.

Example: If an age field accepts values from 18 to 60:

- Valid partition: 25, 40, 55
- Invalid partition: 10, 65

---

## 76. What is Decision Table Testing?

**Answer:**  
Decision Table Testing is used to test different combinations of conditions and the actions expected for each combination.

---

## 77. What is State Transition Testing?

**Answer:**  
State Transition Testing checks how the application behaves when it changes from one state to another.

---

## 78. What is Use Case Testing?

**Answer:**  
Use Case Testing verifies complete user workflows based on how users interact with the application.

---

## 79. What is Error Guessing?

**Answer:**  
Error Guessing is a technique where testers use their experience and knowledge to identify areas where defects are likely to occur.

---

# Real-Time Testing Concepts

## 100. What will you do if a requirement is unclear?

**Answer:**  
If requirements are unclear or missing, I don't make assumptions. I reach out to Business Analysts, Product Owners, developers, or relevant stakeholders for clarification. Meanwhile, I document the queries and propose possible scenarios based on similar features.

---

## 101. What will you do if you find a critical defect just before release?

**Answer:**  
I would immediately report the defect with proper evidence, inform the stakeholders, and communicate its business impact so the team can decide whether to proceed with the release.

---

## 102. What will you do if a developer says your defect is not valid?

**Answer:**  
I would approach it professionally and constructively.

- Provide detailed steps to reproduce the issue.
- Verify the expected behavior against requirements.
- Provide clear evidence showing the issue.
- Be open to discussion instead of arguing.
- If the issue remains unresolved and has a significant impact, discuss it with the relevant stakeholders.

---

## 103. What will you do if a defect cannot be reproduced?

**Answer:**  
I would collect details such as environment, test data, logs, screenshots, and exact steps, and then try to reproduce it again.

---

## 104. What will you do if there is not enough time for complete testing?

**Answer:**  
I would prioritize critical and high-risk functionality first, perform focused testing, and communicate the remaining risks to stakeholders.

---

## 105. What will you do when a build is unstable?

**Answer:**  
I would perform Smoke Testing and report the blocking issues. If critical functionality is not working, I would stop detailed testing until the build is stable.

---

## 106. What if the developer fixes one defect and another functionality breaks?

**Answer:**  
I would report the new defect and perform Regression Testing on the affected and related functionality.

---

# Real-Time Interview Questions

## 143. How do you start testing a new application?

**Answer:**  
First, I understand the requirements and application flow. Then I identify test scenarios, prepare test cases and test data, set up the test environment, execute the tests, report defects, validate fixes, and perform Regression Testing.

---

## 144. How do you test a feature when requirements are not available?

**Answer:**  
I first try to get clarification from the Business Analyst, Product Owner, developer, or other relevant stakeholders. I can also review similar features and existing documentation, but I avoid making assumptions.

---

## 145. How do you handle a production defect?

**Answer:**  
First, I collect all the required details and verify the issue. Then I immediately inform the relevant team, provide clear evidence and business impact, and support the team in validating the fix.

---

## 146. How do you decide what to test first?

**Answer:**  
I prioritize testing based on business impact, critical functionality, risk, frequently used features, and recent code changes.

---

## 147. How do you test when requirements change during a Sprint?

**Answer:**  
First, I understand the updated requirement and identify the impacted functionality. Then I update the test scenarios and test cases, test the changes, and perform Regression Testing where required.

---

## 148. What do you do if testing is blocked?

**Answer:**  
I identify the reason for the blocker, report it to the appropriate team, and continue testing other areas that are not affected while waiting for the issue to be resolved.

---

## 149. What do you do if a developer does not fix a critical defect?

**Answer:**  
I provide clear evidence and explain the business impact. If the issue is still unresolved, I discuss it with the relevant stakeholders so that an appropriate decision can be made.

---

## 150. How do you ensure that all requirements are tested?

**Answer:**  
I review all requirements, create test scenarios and test cases for them, and use a Requirement Traceability Matrix to make sure every requirement is covered.
